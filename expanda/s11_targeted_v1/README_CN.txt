S11 匹配训练与规则改进 v1

目标：在 S11（50 批货、交付时间窗倍率 2）、pop250、B50000 下，分别检验
I/C/M 的规则版是否高于 Base，以及监督 Transformer 是否高于对应规则。
结果可能为负；程序保留失败结果，不强制选出“成功”组件。
旧版回退位置：codex/m-transformer-ppo-threeway 的 cee38b1。
旧 formal_icm_s0_v1、joint_icm_v1、joint_icm_s11_v1、B20 源码和权重不修改。
本目录是新实验，不是对旧实验结果的修正，也不声称新规则与旧运行逐位一致。

固定规模
- 全部使用新 S11 开发实例：2 个规则校准、16 个训练、4 个验证、3 个效果筛查。
- 原始训练 OD 池生成；这些 S11 实例加入开发后，不能再称 S11 为完全未见的泛化配置。
- 实例、优化情景种子、输入源码和模型哈希持久化；同一实例的各方法共用 CCP100 情景。
- 每次完整搜索以 50,000 次真实方案评价为上限，不被 200 代提前截停。
  初始化和可行性增强计费；未改变且已有有效评价的继承个体复用缓存。
  原子交叉对需要两次预算，可能留下最后一次未用预算；实际数量独立记录。
- 不开启最终测试、OOS 重评、PPO、共享网络联合训练，也不自动扩大到 2,700 次旧正式网格。
  本轮标签保存后可用于后续共享监督研究；三个独立组件的新模型不能称为共享网络。

顺序与上限（--stage all 自动完成一次；没有追加调参）
1. 校准：2 实例 x 1 种子 x 7 组 = 14 次完整搜索。
   Base + I/C/M 各自两种预先写定的规则变体。
   LEGACY：I 的原 Directed 全位置选择；C 的 Simple；M 的 Balanced。
   GUARDED：I 保留 Base 的容量/贪心固定位置，仅改随机位置；C/M 在原规则的
   确定性代理容量违反、缺路径、迟到恶化，或任一代理目标恶化超过 2% 时选 Base 候选。
   这是构造期代理，不是真实 CCP 可行性或最终 HV 的保证。
   两个变体在同一新候选构造/随机数协议下比较；LEGACY 指选择规则，不是旧版精确重放。
   按校准集最终 HV 配对均值选每个组件的变体，写入 RULE_SELECTION.json。
   即使校准均值为负也如实记录；不能用校准成绩证明优于 Base。
2. 数据：20 实例各采 I、C、M 一条规则轨迹。I 仅初始化即停止，C/M 分别完整运行。
   60 个任务中 40 条完整搜索、20 条初始化；不用 Base 轨迹冒充规则轨迹。
   I/C/M 预定最多 48/24/48 个状态，覆盖活跃阶段的前中后段。
   每组件每实例额外标注最多 384 次，共最多 23,040 次；实际去重复用数单独记账。
   标注评价副本并恢复随机数状态，标签不影响规则决策，不进入搜索缓存或种群。
   C 候选是交叉加一次相同随机数的 Base 变异后的两个完整子代。
   M 的 K8 含 Balanced、一次提前抽好的 Base 变异子代、最多 6 个替换变体。
   I/C/M 部署都只评价选中的个体/子代对，未选候选无隐藏 CCP 评价。
3. 监督训练：每组件 3 种子，宽度 16，同一网络、30 轮，10/20/30 轮验证。
   从头训练，不加载旧 S0/B400 权重。参考候选预测值恒为 0。
   固定损失 = 加权候选对 softplus 排序损失 + 0.5 x SmoothL1 残差回归损失。
   排序权重是 |标签差| 截断至 [0.1,5]，只用非重复候选，零差不参与排序；
   回归包含所有合法非参考候选，包含零标签，以校准门控所依赖的增益数值。
   标签允许为负，仍为同状态下相对规则的 HV 增量差。
4. 冻结验收：3 新实例 x 3 共同种子 x 7 方法 = 63 次完整搜索。
   Base，I_RULE/I_LEARN，C_RULE/C_LEARN，M_RULE/M_LEARN。
   M 从第 10 代起启用；其他组件保持 Base；相同种子不表示后续搜索轨迹相同。
   不使用筛查结果调参数、重训或挑选部分种子。

总上限：137 个搜索/采集任务，117 次完整搜索 + 20 次初始化。
完整任务与初始化最多 5,855,000 次搜索评价；另加最多 23,040 次标注评价。
训练/额外标注成本、失败尝试和最终比较成本分别保存，不当作免费信息。
两进程耗时需以校准结果估计；旧 S11 单次计时粗算约一天，规则速度变化可能延长。

归一化与输入的严格顺序
1. 保存原始目标、可行性、参考种群原始目标和候选无评价特征。
2. 仅用训练实例的可行轨迹/候选点，按货量/时间跨度单位转换后拟合 HV min/max；
   参考点固定 (1.1,1.1,1.1)，不裁剪超界目标。
3. 用固定训练 HV 文件归一化参考种群，再构造均值/标准差/min/max 等模型上下文。
   进度统一 evaluation/50000；I 另含 slot/population；无 /400、generation/20。
4. 仅用训练状态拟合输入标准化与残差标签尺度；模型输入 z 值截断到 [-10,10]，
   与目标值“不裁剪”区分。部署保存各特征组截断数。
5. 验证仅选择检查点及 lambda={0,.5,1}、阈值={0,.02,.05}（训练标签尺度单位）。
   完全回退规则是允许的验证选择，不能为了“有学习”而禁用该选项。

结果
- RESULT_TABLE.csv / QUICK_RESULT.json：每组件规则 vs Base、学习 vs 规则，区间、胜平负、耗时。
- INSTANCE_BOUNDS.json / PER_RUN.csv：按每实例所有方法/种子的最终可行前沿统一 min/max
  重算最终 HV。此文件仅用于报告，绝不反馈训练或部署。零跨度维度记为 0。
- 同时保存 training_normalization_vs_base；CONVERGENCE.csv 使用冻结训练归一化，
  不把两种 HV 口径混在同一条收敛曲线上。
- 百分比逐实例/种子配对计算，实例等权。参照 HV=0 则百分比空值，报告绝对差，
  不加小常数。区间按实例再按配对种子做 bootstrap，开发选择偏差不包含在区间中。
- acceptance 分开报告“两项均值都正”和“两项 95% 区间下界都正”；全部通过才把
  all_components_met_reliable_gain 标为 true。3 实例小面板不是普适性证明。

运行（在 expanda 下）
  bash s11_targeted_v1/run.sh
默认两个工作进程，输出到 transformer_ppo_runs/diagnostics/ccp_s11_targeted_supervised_v1。
run.sh 前台运行，请在服务器自行通过 nohup 启动。相同目录重复命令会复用已完成任务；
中断任务移至 interrupted 保存后重跑，代码/配置变化须使用新版本输出。
单阶段：python3 -u s11_targeted_v1/run.py --stage prepare|calibrate|collect|train|screen --workers 2
校验：python3 s11_targeted_v1/checks.py（仅正确性样本，不生成研究结果）。
