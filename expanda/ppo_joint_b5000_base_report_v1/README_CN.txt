补齐 PPO 小试的配对 Base 对照

来源：已完成的 ccp_joint_ppo_b5000_pilot_v2。
目标：S0、S4、S8 的第二个验证实例 × 3 个共同算法种子，共 9 对。
使用原 pop250、B5000、100 情景和 /50000 进度特征。不会重新训练 PPO、
改变选中检查点、运行新版本共享策略，或打开最终测试集。

先核验原实验、模型记录、实例和情景的哈希。原 B5000 实验中若存在完全
匹配实例/种子/预算/情景的 Base，则复用；否则仅补跑缺少的 Base。
原来的 27 次 screen Base 与本次 confirmation 验证实例不同，不能用
其总体均值冒充配对 Base。通常本次需要补跑 9 次 Base，最多 45000 次评价。

已有 36 次确认对照记录继续复用：共享监督最高分、PPO最高分、共享监督
概率采样、PPO概率采样，各9次。最高分表示动作 argmax，不是挑选最大HV。

输出使用独立新目录，不覆盖原结果：
results/00_相对Base结果.csv：原冻结训练归一化。
results_union/00_相对Base结果.csv：加入 Base 后，对同一实例汇总全部五种
方法、三个种子及400/1000/5000三个节点的可行目标点，统一min/max，
参考点(1.1,1.1,1.1)，HV不除以1.331。
加入 Base 可能改变边界，因此也重算共享监督和 PPO 的 HV；旧 +1.90%
是相对共享监督的旧报告值，不能直接改名或叠加为相对 Base 的提升。
QUICK_RESULT.json同时保留PPO对共享监督的匹配部署比较。

以平均配对提升、区间、胜平负为主；最大HV为独立描述列。
区间在配置内按实例和种子配对抽样。本确认集每配置只有一个实例，区间
仅反映这几个固定实例的种子波动，不能宣称覆盖整个配置分布。

在 expanda 目录运行：
python3 -u ppo_joint_b5000_base_report_v1/run.py --workers 2

按此前 Base 约32秒/次，9次理论搜索约2.4分钟（两进程）；计入启动、
不同配置和汇总，预计约5–10分钟，以实际负载为准。中断后相同命令续跑。
