S0–S8：冻结共享监督、终局联合 PPO、五组完整预算配对比较

运行入口：bash joint_icm_multiscale_terminal_v1/run.sh
默认输入：transformer_ppo_runs/diagnostics/ccp_icm_multiscale_shared_v1
默认输出：transformer_ppo_runs/diagnostics/ccp_icm_multiscale_joint_v1
默认并发：2。可通过 MAX_WORKERS、MULTI_PPO_ROOT 指定。
输入必须是已经完成的 full-budget shared_model，不能使用 pretrain 或旧 S0 权重。
不覆盖旧目录，不自动启动独立情景评价或最终测试。

固定范围
1. 复用 S0–S8 的 54 个训练实例、18 个验证实例和原始监督标签。
   已完成的共享监督模型、HV 归一化、特征标准化、门控参数保持不变。
2. 用完全相同的监督数据重新训练“ICM 独立 Transformer”对照。
   每个组件有独立主干；每个主干与共享网络结构相同。
   三个训练种子、损失、训练轮次候选、任务/配置平衡及验证选择流程一致。
   独立版参数总量较大；这是共享与独立结构的差异，不宣称参数总量相同。
   不复用旧 S0 的独立模型，也不生成额外标签。
3. 共享监督模型初始化终局 PPO：8 次更新，每次 4 条完整搜索轨迹。
   32 条轨迹按 S0–S8 轮转，每配置 3 或 4 条；实例及种子在运行前固定。
   这不是遍历全部 54 个训练实例，预算受限时按冻结日程选取。
4. update 0、4、8 分别在全部 18 个验证实例上运行一次，共 54 次。
   按“相对 update 0 的最终 HV 配对绝对差”，实例内、配置间等权选择。
   平局选择较早更新，允许 update 0 胜出，绝不强制选择退化的更新。
5. 每配置生成 1 个新开发实例，共 9 个；3 个共同算法种子，5 个方法，
   共 135 次比较。新实例与训练/验证以及旧 B20 筛选实例不重复。
   Base、ICM 启发式、ICM 独立 Transformer、ICM 共享监督、ICM 终局 PPO。

共计最多 221 次完整搜索，11,050,000 次方案评价；不含旧监督数据成本。
每次 pop250、B50000、CCP100、三个 q90 目标，K8，M 从既定第10代后启用。
初始化和可行性增强计入同一预算；有有效缓存且未变化的个体不重复计费。
双子代无法在剩余预算内完成时允许 49,999；提前退出更多则报错。
实现中的高代数保护值不是计划运行代数，主要停止条件始终是方案评价上限。

五组如何执行
Base 沿用冻结的运输模型和原始 I/C/M。
其他四组均用同一个联合控制器，规则候选为 I Directed、C Simple、M Balanced。
I 保留 Base 固定容量/贪心种子，仅在剩余随机初始化位置进行选择。
C 为匹配监督特征，预览“交叉＋Base变异”候选，不调用目标评价；随后恢复
随机数流，取选中的交叉原始子代，再执行真实的 M 一次，最后评价子代。
因而不会在 C 后把子代真实变异两次，也不会因 C 直接完成评价而跳过 M。
学习组合改变状态分布，监督数据与部署轨迹不保证完全同分布；完整搜索
正是检验这种迁移的环节。终局 PPO 直接在该联合流程上收集训练轨迹。
所有方法共用实例、算法种子、情景集和预算；不要求后续随机轨迹相同。

终局 PPO 的含义
三组件共享 actor 主干，各有输入适配；三个集成成员共同参与梯度更新。
增加价值头。每次完整搜索结束的训练归一化可行前沿 HV 是唯一回报。
gamma=1，前面各决策都接收这一终局回报；没有单步 HV 奖励。
采用 clipped PPO，持久 AdamW 状态，2 个优化轮次，KL 保护，按完整轨迹
赋予相等总权重。动作很多的轨迹不会因为样本数多而直接占更大总权重。
训练时在合法候选上按概率采样，原门控均值/方差阈值作为固定分数偏置，
另有 1% 合法候选均匀探索；已完全关闭的组件保持规则动作。
部署与验证确定性选最大分数，update 0 与冻结共享监督规则一致。
更新前核验记录动作概率，禁止拿其他检查点的轨迹作为 on-policy 样本。
按同一批次数分组小批次，无补齐，也不修改训练特征的进度分母 50,000。
终局模型及检查点只能用训练/验证数据选，不使用新开发实例反馈调参。

结果口径
主表：每个新开发实例汇总五组、全部种子的最终可行前沿，确定统一 min/max，
参考点 (1.1,1.1,1.1)，不裁剪，逐次重算 HV，先实例内配对、再配置等权。
该口径只用于报告，不反向进入奖励、归一化训练或检查点选择。
同时保存训练归一化口径的最终比较及预算收敛数据，不能混用两套 HV。
Base HV 为0时百分比留空，报告绝对差；不添加小常数。
95% 区间保留配对关系，对配置内实例及种子分层重采样。
每配置只有1个新实例，因此区间只反映这个固定开发面板的种子波动，
不能声称已估计同配置的实例差异，也不是最终独立测试结论。
保留负结果及 update 0 被选中的情况，不自动扩种子、重采数据或调参。

主要文件
PLAN.json：冻结设置、实例、情景种子、代码/模型哈希、软件环境。
terminal/TRAINING_SCHEDULE.json：预定32条训练轨迹。
terminal/TRAINING_PROGRESS.json：实际优化步骤、验证比较。
terminal/SELECTED.json：最终选择的检查点（可能是0）。
results/00_联合训练对比.csv：五组最终提升、置信区间和搜索时间。
results/STATISTICS.csv：配对提升/绝对差、标准差、置信区间、胜平负。
results/PER_CONFIGURATION.csv、PER_RUN.csv、CONVERGENCE.csv：配置/运行/收敛。
results/INSTANCE_BOUNDS.json：事后 HV 界限。
results/QUICK_RESULT.json：完整比较、训练归一化对照和阶段评价成本。
各运行另存特征截断、调用/回退/切换次数和真实评价计数。

监控与恢复
STATUS.json 和 pipeline.nohup.log 每30秒更新搜索进度，训练时记录阶段。
同一目录有进程锁，禁止重复启动。收到 SIGTERM/SIGINT 会只终止本次
启动的子进程，保留记录；再次执行同一命令复用已完成运行和已完成更新。
未完成搜索从头重跑，其旧目录移到 interrupted，不伪装成续接搜索状态。
已完成搜索计数不包含中断产生的成本；输出明确说明这一限制。
建议用 nohup，结束 tail 的 Ctrl+C 不影响后台实验。

真实 worker 子进程训练/验证和复用。检查数据不属于研究实验。
