# α=(0.8,0.8,0.8) 完整单模型实验

所有文件写入新的 `ccp_alpha08_*` 目录。历史代码、默认参数、权重、搜索结果和正在运行的 α=0.9 复评均不修改。当前程序不会远程启动任务，需要在 41 执行入口。

## 三个数的含义

优化仍使用 100 个共同优化场景，三个目标都取第 80 小的值。每次搜索种群为 250，评价上限为 5,000，保留原停止规则（实际 4,999 或 5,000）。

每个 **实例 × 方法 × 搜索种子** 保留一个最终可行非支配解集，包含完整路径和份额。对同一解集分别用独立的 100、1,000、5,000 个场景重新评价，三个目标分别取第 80、800、4,000 小的值。三组不嵌套、与优化场景的随机种子不重合；同实例所有方法和搜索种子共享场景。400 和 1,000 次搜索检查点不进入新报告。

## 自动执行顺序

1. 只读核对当前 Table 5/6/7 的 810 次记录及训练/验证实例；只复用实例定义、网络、路径库、采样器和算法实现，不复用 P90 标签、权重或搜索结果。
2. 按原协议重新采集 P80 数据：S0–S8 每配置 6 个训练实例、2 个验证实例；共 72 条 Base 采集轨迹（每条上限 50,000）和 72 次初始化采集。每实例 I/C/M 的采样上限仍为 48/24/48。保留原采样位置、进度特征和 M 启用时点。
3. 共享监督、独立监督都重新训练，仅用 seed 991001。按原规则比较 epoch 10/20/30、阈值 0/0.02/0.05 及始终保留规则选项，不固定旧模型选出的 epoch 20 和阈值。两组使用相同的新数据及训练归一化。
4. 从新共享监督开始 PPO。先在训练实例进行 9 次贪心搜索获取温度校准输入；再进行 3 次更新，每次 9 条策略轨迹覆盖 S0–S8，并分别配 9 条冻结共享策略搜索。保持原 PPO 公式、学习率、48 步上限、KL、温度网格等；只用验证实例在 u0/u1/u2/u3 中选模型，另一组验证实例确认，不再选模型。
5. 重跑主面板：Table 5 为 13 方法 × 54 次=702；Table 6 为 Base/shared/PPO × 27 次=81；Table 7 为小网络 Base/shared、大网络 shared 共 27 次。810 次均为新的 P80 搜索。Table 7 使用原固定路径库及大小网络共有随机实现。
6. 对全部保存的最终决策先用原优化场景复算 P80，必须逐解复现才开始样本外评价。随后复评 100/1,000/5,000 场景，按全部方法/种子/三组目标点在实例内取共同边界；Table 7 同一对网络共用边界。参考点 1.1³，HV 除以 1.331。

## 两个消融的明确口径

随机组以本轮 P80 shared 的 54 次运行中各组件 `switches/calls` 为目标，沿用 v2 的在线累计比例控制，仅在有合法非规则候选时均匀选择。实际比例不保证完全匹配，报告目标、实际比例及差异，同时保存所有方法的合法决策数。不会把 0.9 的 98.1/43.3/32.9 当成本轮目标。

零阈值组将**启用组件**的阈值设为零；验证选择始终保留规则的组件仍保持禁用。合法掩码及规则候选仍然保留，因此它不是“强制每次替换”。如本轮验证全部选零，该消融可能与 shared 相同，仍如实记录。

## 启动与进度

```bash
bash alpha08_main_v1/launch.sh 1
```

脚本先在前台核对来源，通过后转后台运行并打印 PID 和日志位置。也可直接前台执行 `python3 -B -u alpha08_main_v1/run.py --workers 1`。

默认输出：`transformer_ppo_runs/diagnostics/ccp_alpha08_single_full_v1`。也可指定全新的 `--out`。首次只核对可加 `--prepare-only`；有 PLAN 后重复同一命令会继续，不覆盖已完成任务。失败的未完成搜索目录重命名保存；完成任务须校验哈希才复用。

默认单计算进程、每进程单线程、nice 10，减少与 α=0.9 复评的资源争用；同时运行仍可能使两项任务变慢。`--workers 2`（后台脚本参数 `2`）只控制搜索/采集并行；训练和复评始终单进程。STATUS 中 ETA 仅覆盖当前阶段，不是整个实验的完成时间。搜索记录保存系统负载、线程数和优先级，耗时比较应说明运行负载。

```bash
cat transformer_ppo_runs/diagnostics/ccp_alpha08_single_full_v1/STATUS.json
cat transformer_ppo_runs/diagnostics/ccp_alpha08_single_full_v1/SL_SELECTION.json
cat transformer_ppo_runs/diagnostics/ccp_alpha08_single_full_v1/ppo/SELECTION.json
cat transformer_ppo_runs/diagnostics/ccp_alpha08_single_full_v1/oos/RESULT_LOCATION.json
```

报告目录由最后一个 JSON 给出。`MAIN_5000.csv` 为主结果，`CONTRAST_1000.csv` 为对照，`ALL_SCENARIO_SUMMARY.csv` 含 100 场景。另存逐运行 HV、最终方案数、逐解/逐方法 P80 样本内与样本外变化、场景组之间 HV 差。

`P80_COVERAGE_PER_RUN.csv` 报告 P80 覆盖率及低于 0.75 的比例。复用评价报告中的 `fraction_below_085` 字段仍明确表示 0.85，不作为 P80 覆盖不足的阈值。当前复评导出不计算置信区间，不复用旧报告的置信区间。

PLAN 记录 commit、代码和原始文件哈希、全部实例和随机种子；各次搜索保存实际评价次数、用时和最终决策。只改变置信水平及由新训练/验证得出的模型与阈值，不调整分布、CV、封顶、均值校准、候选构造或搜索默认行为。
