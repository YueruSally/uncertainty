S11 小试学习诊断：只读，不重新搜索或训练

用途：区分规则本身不适合、候选标签没有可学习空间、训练没有拟合好、以及
训练到验证的差距。单个验证实例无法确证跨实例泛化，更不能保证扩大数据后改善。

运行：
python3 -u s11_pilot_learning_audit_v1/audit.py --source transformer_ppo_runs/diagnostics/ccp_s11_targeted_pilot_v1

程序读取冻结的训练/验证候选原始目标、三个训练种子在 10/20/30 轮的检查点。
核验模型、数据及实际调用的标签/特征/HV代码哈希；源目录不会被修改。
输出在旁边的 ccp_s11_targeted_pilot_v1_learning_audit_v1 目录。

AUDIT.json 为完整报告，QUICK_RESULT.json 去掉分阶段标签细表。
终端打印所有组件的标签空间、训练/验证选择收益、旧训练损失、验证重放误差、
特征截断和目标超出 HV 参考点的情况。没有任何新运输方案评价。

解释：
1. positive-opportunity 是已标注状态中有候选优于规则的状态数。
   all-tied 是全部合法候选标签相同的状态数。oracle 为逐状态事后最好残差均值，
   不可作为可部署模型或最终搜索收益。
2. fixed-rule-threshold 使用各轮既有集成，固定 lambda=0、阈值=0，保留规则
   候选得分为0。不强迫选择负分候选，仅诊断原始排序；不改变部署门控。
3. 所有 gain 均为原训练归一化下的单步 HV 残差，不是最终 HV 的百分比。
4. 训练收益为正、验证收益差：支持泛化差距；还应看随轮数变化及标签空间差异。
   训练、验证都差且 oracle 明显为正：优先查拟合、特征与损失是否对齐。
   两者 oracle 都接近0/标签大多打平：即时标签信号弱，不等于终局搜索没有空间。
   训练损失下降但验证选择收益不改善，才有依据进一步怀疑过拟合或代理目标不一致。
5. 原验证重放误差非零或选择比例不一致时，先排查软件版本/数值差异，再解释结果。
   数据和代码哈希不一致时直接停止，避免混用实验版本。
6. 规则相对 Base 的搜索退步，不能归因于被关闭的学习模型；这是另一个问题。

限制：训练/验证只来自2/1个实例，同一轨迹内状态相关。诊断不使用筛选结果调参，
不更换规则、不启用已关闭门控、不补采、不启动 PPO，也不自动扩大实验。
