# CCP-I Directed Balanced v1

## 版本定位

这是当前完成冻结 CCP 优化验证和独立情景复评的 **I（初始化）规则版本**。

- 冻结策略名：`I_DIRECTED_BALANCED`
- 规则配置名：`joint_balanced`
- 核心实现提交：`62bec13`
- 优化评价：成本、排放、完成时间分别取 q90；HV 使用训练专用固定归一化。
- 结论边界：这是确定性的 Directed Balanced 初始化教师/规则，不是 PPO 自主学习结果。
- 验证结论：平均效果和独立 OOS 泛化通过；预先设定的逐运行安全门槛未完全通过。

## 我们修改了什么

### 1. 保留 Base 初始化结构，只控制 8 个随机个体

人口规模为 20。Base 原本包含：

- 6 个容量感知可行种子；
- 2 个最低成本种子；
- 2 个最短时间种子；
- 2 个最低排放种子；
- 8 个随机初始化个体。

I 规则完整保留前 12 个 Base 种子，只替换最后 8 个随机个体的路径身份。对于每个被控制个体，仍保留 Base 随机流产生的：

- 每个批次使用的路径数量 `k`；
- 各路径分配比例；
- Python 随机数消耗顺序。

因此 I 与 Base 的差异集中在“选择哪些路径”，而不是人口规模、评价预算或分配比例。

### 2. 使用与 M 一致的五类路径信号

对一个批次的所有候选路径计算：

1. `批量 × 单位运输成本`；
2. `批量 × 单位排放`；
3. 名义运输时间；
4. 最大迟到时间；
5. 负的准时概率。

先把结构可行路径的五列信号分别做批次内 min-max 缩放，然后计算：

```text
balanced_score = scaled_cost + scaled_emission
                 + (scaled_time + scaled_lateness
                    + scaled_negative_reliability) / 3
```

结构可行性是硬优先级。每个批次按照分数从小到大选择前 `k` 条路径，再使用 Base 已经生成的分配比例。

### 3. 不增加真实目标评价次数

正式 `joint_balanced` 规则只使用路径库和可靠性代理量排序，不额外调用 CCP 目标函数。Base 和 I 都使用：

- 200 个冻结 SAA 情景；
- `alpha = 0.90`；
- 400 次真实目标评价；
- 人口 20；
- 相同算法种子、CCP 情景、归一化和参考点。

### 4. 完整实验流程

1. **规则筛选（3 个开发种子）**：比较 Balanced、Diverse 和 Reliability，Balanced 最好。
2. **强度筛选**：比较 25%、50%、75% 和 100% Directed；100% Directed 的平均值、中位数和胜率最好。
3. **留出验证（7 个新算法种子）**：10 个实例 × 7 个种子，共 70 对 Base/I。
4. **独立 OOS 复评**：冻结上述 70 对最终 Pareto 解，不重新优化，在一套共同的 1000 个全新情景中重算三个 q90 和 HV。

完整数字见 [RESULTS.json](RESULTS.json)。

## 主要结果

### 冻结 CCP 优化内的 held-out 70 对结果

- 平均 HV 提升：**+22.4567%**
- 95% CI：**[+16.0208%, +28.8926%]**
- 中位数：**+11.5189%**
- 58 胜 / 0 平 / 12 负
- 47/70 次提升至少 5%
- 38/70 次提升至少 10%

### 1000 个独立新情景上的 held-out 70 对结果

- 平均 HV 提升：**+16.3451%**
- 95% CI：**[+12.0616%, +20.6285%]**
- 中位数：**+15.8099%**
- 53 胜 / 0 平 / 17 负
- 47/70 次提升至少 5%
- 41/70 次提升至少 10%

因此可以严谨地说：**Balanced-I 在独立不确定性情景上的平均提升超过 10%，且 95% 置信区间下界仍超过 10%。**

但不能声称所有运行都更好。预设安全门槛要求胜率至少 80%、损失率不超过 20%；实际胜率为 75.71%、损失率为 24.29%。主要尾部风险集中在 `S0_007`、`S0_009` 和 `S0_012`。

## 为什么 HV gate 被淘汰

为了减少尾部损失，曾测试 `joint_balanced_hv_gate`：同时评价 8 个 Directed 个体和对应的 8 个 Base 个体，再根据初始 q90-HV 选择整套初始化。

这会额外消耗 8 次真实评价。在总预算仍为 400 时：

```text
Base       = 20 次初始化 + 380 次后续搜索
HV gate    = 28 次初始化比较 + 372 次后续搜索
```

所以即使 gate 选择 Base，也无法原样回退到 Base；它少了 8 次后续搜索评价。同时，初始 HV 对第 400 次评价时的最终 HV 预测不够稳定。fresh 70 对验证中 gate 只有 33 胜、6 平、31 负，最差为 -22.74%，因此正式版本不使用 HV gate。

相关代码和失败记录保留用于审计，但正式入口只使用 `joint_balanced`。

## 如何运行

进入 `expanda` 后，冻结 CCP 留出验证入口为：

```bash
bash run_i_directed_balanced_validation_v1.sh
```

独立 OOS 复评入口为：

```bash
bash run_i_directed_balanced_oos_v1.sh
```

服务器上的证据目录：

```text
transformer_ppo_runs/diagnostics/ccp_i_directed_balanced_validation_v1_10inst_holdout7seed_b400
transformer_ppo_runs/diagnostics/ccp_i_directed_balanced_oos_v1_10inst_holdout7seed_s1000
```

源码包不包含服务器实例 JSON、训练专用归一化文件和大体积逐运行输出。运行脚本前需要设置 `INSTANCES`、`NORMALIZATION` 和相应的证据根目录。
