# I 和 C 的下一步实施计划

## 总体顺序

M 的 Directed Balanced v1 立即冻结。后续按以下顺序推进：

1. I 单组件规则教师；
2. C 单组件规则教师；
3. I Actor 学习教师门控；
4. C Actor 学习教师门控；
5. 分别验证 `I`、`C`、`M`；
6. 再验证 `IM`、`CM`、`ICM` 的增量，不把 ICM 当作唯一主结果。

所有开发使用冻结的 200 个优化情景。当前 OOS-1000 不再用于选规则、权重或阈值；最终保留新的共同 OOS-5000。

## I：初始化组件

### I-1 先建立规则教师

目标不是让所有初始个体选择同一条最低成本路径，而是构造一个兼顾质量与多样性的初始种群。

对每个批次的候选路径计算与 M 一致的五类代理信息：成本、排放、名义时间、迟到、准时可靠性。先生成三个方向的候选：

- Balanced：综合五类代理量；
- Cost/Emission extreme：保留目标边界；
- Time/Reliability extreme：保留时间与风险边界。

用确定性的轮换或分层配额填充初始种群，禁止 20 个个体坍缩成同一方案。初始种群必须同时满足结构可行性和路径唯一性下限。

### I-2 快速筛选与正式验证

- 快速筛选：10 个实例 × 3 个开发种子，预算 400；比较 Base-I 与 Teacher-I。
- 入场标准：平均 HV 至少 +5%，胜率至少 70%，最差配对不低于 -5%。
- 正式 held-out：相同 10 个实例 × 7 个新种子。
- 通过后才训练 I Actor；Actor 的安全动作是 Teacher-I，不是随机 Base 初始化。

### I-3 I Actor 学什么

Actor 只学习：

- 每个初始个体采用哪一类教师方向；
- 教师候选之间的有限权重/配额调整；
- 低置信度时回退已经验证的 Teacher-I。

不再用稀疏的最终 HV 单次回报直接从零学习整条路径。

## C：交叉组件

### C-1 先建立联合交叉规则教师

一次 C 决策必须是完整的联合动作：父代对、交叉批次/公共节点、cut 位置以及 Base passthrough。不能把每个 cut 当成独立 PPO 动作。

不增加真实目标评价次数，先用子代代理变化给每个联合候选打分：

- 代理成本和排放变化；
- 名义时间、迟到与可靠性变化；
- 两个子代相对父代的路径有效性；
- 子代之间和当前种群之间的多样性；
- 结构不可行候选直接屏蔽。

保留 `base_passthrough` 作为安全动作，选择最小 Balanced 代理分数的合法联合交叉动作。

### C-2 快速筛选与正式验证

- 快速筛选：10 个实例 × 3 个开发种子，预算 400；比较 Base-C 与 Teacher-C。
- 先测试交叉开始代数和使用频率的少量大步网格，不再做大量微小超参数试验。
- 入场标准与 I 相同：平均至少 +5%、胜率至少 70%、最差不低于 -5%。
- 正式 held-out 使用 7 个新种子，随后才训练 C Actor。

### C-3 C Actor 学什么

Actor 学习 Teacher-C 与 `base_passthrough` 的门控，以及教师前几名联合动作之间的调整。低置信度回退 Teacher-C/Base，不允许学习策略把当前稳定的 M 结果拉低。

## 组合阶段

组合阶段采用逐项增量：

1. 固定 M v1，加入 I，比较 `M` 与 `IM`；
2. 固定 M v1，加入 C，比较 `M` 与 `CM`；
3. 只有 I 和 C 各自通过 held-out，才比较 `M`、`IM`、`CM`、`ICM`；
4. 使用完全相同的实例、种子、预算、冻结 CCP 情景和归一化；
5. 最终只运行一次新的共同 OOS-5000，不用该结果继续调参。

## 预期时间

- I 规则教师实现与单元测试：约 30–45 分钟；3-seed 快筛约 20–40 分钟。
- C 规则教师实现与单元测试：约 45–60 分钟；3-seed 快筛约 20–40 分钟。
- 每个组件的 7-seed held-out：取决于并行终端/核数，通常约 30–60 分钟。

每一步在运行前都应报告预计时间、输出根目录、进程数和完成判断命令。
