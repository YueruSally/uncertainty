# 单模型 B5000 离线核对：步骤1—3

入口 `python3 -u single_b5000_offline_review_v1/run.py`。
默认读取已完成的 `ccp_icm_single_member_second_instance_b5000_v1`，
输出到同级新目录 `ccp_single_b5000_offline_review_v1`。
不修改旧搜索、旧报告、权重、阈值、训练代码；不训练，不运行搜索，不调用运输方案评价。

## 做什么

1. 校验594次已保存搜索（11种方法×54对）的实例、种子、成员、预算节点，
   记录逐文件SHA256；复制计划、结果表和当前三个部署模型到审计快照。
   原始运行只读取并记录哈希，不额外复制大型前沿。输出 `SAVED_RUNS.csv`、
   `INPUTS.json`、`RUNTIME_PROVENANCE.csv` 和 `snapshot/`。
2. 对源模型清单中已经保存的训练和验证 DATA.json 校验哈希和角色。
   统计I/C/M在≤1000、1000–5000、>5000三个阶段，以及≤5000合计的状态数、
   实例数、合法非规则候选数、至少一个可行子代的候选数、非零标签和排序信号。
   使用保存的目标值重算相对规则候选的单步HV标签，记录当前单成员选择与替换率。
   不增加目标评价。训练状态只作描述，模型/门控的重选只读验证状态。
3. 固定训练成员991001，逐一读取独立监督和共享监督第10、20、30轮的保留权重。
   使用≤5000的验证状态，原输入缩放、原训练HV边界、原进度分母50000不变；
   比较原阈值网格0、0.02、0.05及始终保留规则。单成员标准差为零，lambda固定0。
   各组件按实例先平均、再按配置等权，标签除以原训练目标标准差；
   全模型轮次按三个组件等权选取，平分优先较少替换，再优先较早轮次。
   仅输出建议，不导出/替换BUNDLE或新权重、不启动确认搜索。
   同时读取PPO协议、检查点、原训练及配对参考记录，验证保存的奖励是否为配对HV差，
   记录实际配置与轨迹数、含u0和仅更新后检查点的选择规则。

独立ICM仍是每个组件一套独立网络；每个组件仅使用一个成员。
共享监督及PPO部署均只使用一个成员。本次不评价或平均其他成员。
PPO历史训练与验证记录用于溯源，不冒充单成员重新训练/验证。

## 看哪些文件

- `STATUS.json`：进度、是否结束、有无警告。
- `REPORT_CN.md`：中文摘要和下一步待处理事项。
- `STATE_COUNTS.csv`：先生成的状态覆盖计数，尚未重算标签也能查看。
- `STATE_COVERAGE.csv`、`LABEL_SIGNAL.csv`：覆盖和标签信号；空阶段明确为0状态。
- `SINGLE_POLICY_AUDIT.csv`：当前单成员按角色、配置、阶段的替换率及单步标签收益。
- `PER_STATE.csv`：逐状态审计；不是400/1000次搜索的胜平负表。
- `GATE_CANDIDATES.csv`：所有有效轮次/阈值选择分数。
- `PROPOSED_SELECTION.json`、`SUPERVISED_SELECTION.csv`：建议与原方案是否变化。
- `CHECKPOINT_AVAILABILITY.csv`：保留权重是否齐全；缺少轮次不会被静默忽略。
- `PPO_PROVENANCE.json`、`PPO_TRAINING_PAIRS.csv`：PPO实际训练和奖励证据。

CSV使用UTF-8 BOM，可在VS Code或Excel按UTF-8打开。
标签/推理结果缓存写在新目录；中断后重复同一命令复用缓存。
再次运行已完成目录会核验原输入哈希后退出。输入改变则停止，不能覆盖已冻结审计。
定期输出心跳。默认两个标签计算子进程（`--label-workers 2`），外加一个调度进程；
模型推理为单线程CPU，不需要GPU。可设置 `--label-workers 1` 降低CPU占用。

## 解释限制

本次不重新审计CCP评价器、不重新计算594条搜索HV；它们属于已有运行记录。
原始输入哈希一致只证明本次读取/比较来源一致，不能证明算法在所有实例上获胜。
验证集已用于旧模型选择，本次重选是开发诊断，不是独立最终效果证明。
少量前期状态选出不同阈值不等于部署会改善；是否补采数据、做完整B5000验证、
重新训练或补消融，必须看这些输出后再决定，程序不会自动继续。
现有54对开发结果不参与本次模型选择，全部保留。
