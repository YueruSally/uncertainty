# M 完整搜索反馈实验

`run_m_terminal_feedback_v3.sh` 复用已完成的 `single-intervention-ppo-v2`。仍在第一个可用 G10+ 决策点选择一次，其余执行原 Balanced；所有搜索为 CCP100、pop20、B400。

1. 读取原 64 条训练轨迹及配对 Balanced。只补跑缺失的合法动作，各自执行到搜索结束；这些完整反事实搜索全部计入训练成本。
2. 使用全部动作的最终 `HV/HV_Balanced−1` 训练 Transformer，目标为概率加权的期望回报。训练使用 6 个实例，014/016 两个实例仅用于验证；原预训练模型不得用过这两个实例。
3. 全反馈训练最多 40 轮，固定每 5 轮验证。接着做 4 次真正的在线 PPO 更新：每次 6 个完整搜索、各一条学习决策。仅用当前策略采样的数据更新 PPO。
4. 验证直接对保存的各分支结果按策略概率求期望；这不是取最好分支。最终在 021/022 的原 20 个配对种子上实际运行预训练与 PPO 策略，并复用完整匹配的 Balanced。

部署只执行一个采样动作，无额外候选评价。最终表同时给出 Balanced、全反馈预训练和预训练后 PPO。选择 PPO 第 0 次时会明确标记，不能宣称 PPO 产生增益。

新搜索数为 `缺失动作分支数 + 48 次 PPO/配对基线 + 80 次开发搜索`，至多 384 次，每次 400 次评价。旧实验、原预训练和中断成本另行披露。Balanced 耗时来自已完成的源实验，不用于声称严格的同时硬件加速优势。

在 `expanda` 中设置 `INSTANCES`、`NORMALIZATION`，执行：

```bash
export SOURCE_ROOT=transformer_ppo_runs/diagnostics/ccp_m_single_intervention_ppo_v2
export OUT_ROOT=transformer_ppo_runs/diagnostics/ccp_m_complete_terminal_feedback_v3
bash experiments/run_m_terminal_feedback_v3.sh
```

进度是 `STATUS.json`，训练是 `PRETRAINING.json` 和 `TRAINING_PROGRESS.json`，最终结果是 `RESULT_TABLE.csv`、`QUICK_RESULT.json`。一次调用限 45 分钟；同一命令续跑复用分支与已提交更新。通过仍需新实例和独立情景验证。

思路参考 [Bertsekas、Tsitsiklis、Wu 的 rollout 方法](https://www.mit.edu/~dimitrib/rollout.pdf)：尝试一个动作后沿用基准策略，用后续完整结果评价该动作。本文的完整反馈用于训练近似网络；其泛化或性能改进没有该论文条件性理论保证。

## 固定延长训练：40 → 400 步

`extend_terminal_feedback_training.py --source <完整 v3 输出目录>` 只读取已保存的动作最终收益，不启动搜索或 PPO。数据、网络、学习率、损失和实例划分不变；先从原始权重重建 Adam 前 40 步，核对旧训练指标和选中权重完全复现，再训练至 400 步。新增选模点预先固定为 80、120、200、300、400，保留原模型作对照。运行上限 120 秒，输出到源目录下独立的 `training_extension_400_v1`。

结果是两个验证实例上基于已存分支的条件期望收益，不是新的搜索结果。只有两个实例均为正才建议小预算实际搜索；不自动启动搜索或 PPO。重复使用这些验证实例属于开发过程，仍需全新实例确认。完成后直接打印结果表，重复执行复用已完成结果。

`check_terminal_decoding.py --source <同一 v3 输出目录>` 固定延长试验已经选中的权重，只比较原概率抽样与最大概率动作（并列时选 Balanced）。只查已有分支结果，不扫描温度或阈值、不训练、不新增目标评价。输出逐实例条件收益和动作比例；标签只用于评分，不参与选择动作。该比较属于新的部署规则诊断，不能称为修复代码错误或 PPO 收益；即使验证为正，仍须实际搜索和独立确认。

## 扩大训练实例覆盖

`expand_terminal_training_instances.py --source <同一 v3 输出目录>` 增加训练实例 011、015、017、018、019、020，各用固定种子 902001–902008。它们来自已有训练目录，不属于新独立测试集。新增实例不得与原训练、验证、开发实例重名或具有相同批次内容。只新增 48 个训练状态，原 48 个训练状态和 014/016 的 16 个验证状态全部保留。

每个新状态先执行 Balanced，再补齐其余合法动作的完整终局反馈。共至多 240 次 CCP100/pop20/B400 搜索（96,000 次评价），所有分支均计入训练成本。复用同一个实际算子执行函数，核对相同初始种群、情景、动作前输入和预算。2 个单线程工作进程，单次调用限 30 分钟；同一命令可复用已完成分支和已提交训练。

网络、特征归一化、原始预训练初始化、学习率及损失不变，训练 400 步；收益尺度仍只从训练数据计算。固定在 40、80、120、200、300、400 步选模。报告原 6 实例和扩展 12 实例模型在相同验证状态上的 softmax 期望收益与 argmax 收益。只有两个验证实例的 argmax 收益均为正，才建议冻结该策略做实际搜索；不会自动启动搜索或 PPO。选中模型标记为 `single-intervention-argmax`，不得交给旧的随机抽样执行器。最终仍需新实例与独立情景确认。

默认结果目录为 v3 同级的 `ccp_m_terminal_coverage_12inst_v1`。进度见 `STATUS.json`，最终见 `RESULT_TABLE.csv` 和 `QUICK_RESULT.json`，成本包含本轮完整搜索、原实验成本及未提交中断成本的说明。

# M 候选预筛选方案（K8 采集阶段）

`m_prescreen_protocol_v1.json` 固定 CCP100、pop20、B400、K8 候选、训练/验证/开发实例及最终独立测试的生成种子。候选 0 必须是当前 Balanced 的原样子代。在线只评价模型选中的一个子代；训练时额外评价的候选逐个单独计费。当前旧日志没有证实可直接提取大量完整染色体标签，原 384 状态审计也不是 K8 候选集。

`audit_m_prescreen_data.py` 只盘点现有日志；其中 `mutation_outcomes.jsonl` 多数只记动作，零条 q90 不表示其他文件没有目标标签。`run_m_prescreen_k8_collect.py` 已实现 K8 采集：在训练和验证实例上以 Balanced 搜索，每个采集状态原样保留 Balanced 子代，另外构造最多七个不重复的合法 Replace 子代。采集额外评价的子代计入 `training_feedback_evaluations`，不进入 B400 搜索评价预算。每条反馈保存动作前种群、候选批次 token、候选目标值、可行性和真实单步 HV 贡献。

K8 采集阶段不训练模型、不运行开发或最终测试。Balanced 候选在列表中只是回退选项，不能保证最终 HV 下限。已完成的固定偏好实验不重跑，其事后实例最优收益只作为诊断。

`train_m_prescreen_surrogate.py` 只读取已完成的 K8 数据。它用 6 个训练实例拟合 3 个小型 Transformer，在预先指定的 014/016 两个实例上选择训练轮次并执行一次固定离线门。网络预测候选的归一化 CCP100 三目标和可行性；选择器把预测点加入动作前种群，按固定参考点计算预测 HV 贡献。通过条件是两个验证实例的真实净收益均为正且发生过非 Balanced 选择。没有阈值扫描；不新增目标评价、搜索或 PPO。只有通过后才实现配对 B400 搜索。

绝对目标代理在 014/016 上因跨实例尺度误差而全部退回 Balanced，但两个实例的 K8 oracle 均为正。`ranker_v2` 因此在查看新数据前冻结为直接预测“候选单步 HV 贡献减 Balanced 贡献”。014/016 只保留为开发诊断；`run_m_prescreen_k8_collect.py --design ranker-v2` 使用 017/018 和固定种子采集新的验证面板。`train_m_prescreen_ranker_v2.py` 仍只用原 6 个训练实例拟合，Balanced 分数固定为零，3 模型均值按 argmax 选择且并列回退 Balanced。只有 017 和 018 的实际平均净收益都为正且各自发生切换，才允许进入完整搜索。

上述跨实例 `ranker_v2` 在执行新验证前已被实例内方案取代，命令会主动拒绝启动。`check_m_prescreen_within_instance.py` 只读 014/016 已有 K8 轨迹，在每条轨迹内部按时间一分为二：前半段独立拟合归一化和 3 个同结构增益 Transformer，固定训练 80 轮；后半段只测试，不选轮次或阈值。两实例后半段平均净收益均为正且都有切换，才支持把预训练加实例在线更新接入 B400 搜索；否则结束 K8 预筛选分支。

`run_m_prescreen_final_oracle_v1.py` 是停止扩数据前的最终机制上限审计。它在 021/022/023 三个开发实例、10 个固定种子上比较 Balanced、无需目标评价的三目标名义增量简单评分，以及贪心 K8 oracle。oracle 每次用冻结的 CCP100 评价整个候选池，按当前种群的一步真实 HV 贡献选一个子代；选中子代计入 B400，其余评价全部作为诊断成本单列。因此它不是可部署的等成本算法，也不是全轨迹回溯最优。只有三个实例均不为负且等实例平均最终 HV 提升至少 1%，才扩大到 25/50/100/200 个训练实例；否则停止 K8 预筛选。锁定的最终测试实例不会被打开。

oracle 审计以三个实例均为正、等实例平均 `+4.992%` 通过。`run_m_prescreen_scale_v1.sh` 因此生成训练侧 OD 域的 200 个 S0 训练实例和 20 个固定验证实例；生成、CCP、算法种子使用 93M/95M/96M 命名空间，与 98M 的锁定最终测试严格分离。每条 B400 轨迹在 G10 后采集实际存在的 12–30 个 exact-K8 状态，再按时间顺序分成早、中、晚三段且每段至少 4 个；每状态保存 8 个完整候选标签。正常搜索固定为 88,000 次评价，标签评价按实际状态数乘 7 单独计费，上限为 46,200 次。

同一数据按哈希固定顺序形成 25/50/100/200 个实例的嵌套训练集。小型 width-16 Transformer 固定训练 30 轮，使用纯状态内、按真实差值幅度加权的成对排序损失；三个固定训练种子取均值。20 个验证实例不选择轮次、阈值、网络或随机种子。只有 200 实例模型平均净收益为正、至少 12/20 个实例为正、对 log2 实例数的学习曲线斜率为正，且优于 25 实例模型，才冻结模型进入一次配对 B400 搜索；否则停止该路线。

实际学习曲线在四个规模上平均净收益均为正，200 实例模型覆盖 12/20 个正实例并捕获 17.1% 的一步 oracle 收益，但随实例数增加的斜率为负，因此原门仍判失败。`run_m_prescreen_scale_search_v1.sh` 是一次明示的探索性例外：不修改、不重训 size-200 三模型集成，在 97M 独立种子新生成的三个训练域开发实例上，各用 10 个配对种子比较 Balanced 与 Transformer。两种方法均为 CCP100/pop20/B400，只评价最终选择的一个 K8 子代；不运行 PPO、不打开 98M 最终测试。只有三个实例的平均最终 HV 差都为正且发生过切换，才允许一次有上限的 PPO 实验。

上述完整搜索以三个实例全部为正、等实例平均 `+3.658%` 通过。PPO 之前由 `run_m_prescreen_review_v1.sh` 完成三项审稿核查：在相同三实例和十种子上补跑无需隐藏评价的 K8 简单评分与单步贪心真实-HV oracle；随后对 Balanced、简单评分、冻结 Transformer 和 oracle 的最终前沿使用同一套独立 OOS1000 情景重评，并采用一个四方法共同参考点。贪心 oracle 不是最终轨迹的数学上界，Transformer 超过它会被标记并检查，但不能单独证明错误。脚本在任何新运行前保存冻结模型清单，包括 checkpoint 哈希、执行代码提交、训练/验证实例、训练种子、损失和配置；核查完成前不启动 PPO，也不打开最终测试。

`run_m_prescreen_ppo_v1.sh` 在审稿核查通过后完成论文所需的 Transformer-PPO 阶段。PPO 梯度只使用 200 个训练实例已经保存的 exact-K8 候选反馈，固定执行 8 次 `gamma=0` 更新并保存 0/2/4/8。更新 0 是监督 Transformer 对照，不可伪装成 PPO；真正的 PPO checkpoint 只能从更新 2/4/8 中选择。

选模阶段对每个候选 checkpoint 在全部 20 个验证实例上各执行一次完整 CCP100、pop20、B400 搜索，共 80 次搜索。验证实例不参与梯度；按相对更新 0 的平均最终 HV 选择 PPO checkpoint，并在并列时依次采用更多正实例和更早更新。结束后 `FROZEN_FORMAL_METHODS.json` 同时冻结监督 Transformer 与验证选中的 Transformer-PPO。该流程不读取 97M 的开发搜索输出来选模，也不打开 98M 的最终测试；下一步正式实验必须同时加载这两个冻结方法。

20实例验证从真正的PPO更新2/4/8中选中更新2；其验证均值相对监督模型为负，因此PPO保留为论文要求的冻结消融，而不是事后删除。`run_m_prescreen_formal_v1.sh` 首次打开98M锁定测试，只比较 Base、Balanced、监督Transformer和PPO-U002；不包含简单K8。10个最终实例各用10个配对种子，全部保持CCP100、pop20、B400。随后对四种方法的最终前沿按每实例预先冻结的独立种子做OOS5000重评，并使用四方法共同HV参考点。

正式实验一旦生成最终实例即写入`FINAL_TEST_OPENED`，结果不得用于重新选择模型、阈值、checkpoint或实验尺度。`pop250 × 200代`约需5万次评价，且超出B400模型的训练分布，不能在本轮临时替换；如需报告，应作为重新训练、重新验证的独立规模扩展实验。

`recompute_m_prescreen_formal_statistics_v1.py`只修正正式报告的两层bootstrap：先有放回抽取10个实例，再在每个被抽实例内有放回抽取全部10个配对算法种子。初版误为每个被抽实例只取一个种子，因而夸大区间宽度。修正脚本只读取已保存的400次搜索和100条OOS结果，在独立目录写报告；原始HV、均值和胜/平/负不变，不新增评价且不覆盖锁定结果。
